# @microsoft/rayfin-data Agent Instructions

## Commands

Run these from `packages/typescript-sdk/data/`.

- Build in watch mode: `rushx build:watch`
- Run tests: `rushx test`
- Test watch mode: `rushx test:watch`
- Test coverage: `rushx test:coverage`

## Architecture

- Entrypoint `DataApi<TSchema>` in `src/client/DataApi.ts` exposes:
  - `rest.<Entity>`: REST client with OData query options (`$filter`, `$orderby`, `$top`, `$skip`, `$expand`, `$select`).
  - `gql.<Entity>`: GraphQL fluent client with `select`, `where`, `orderBy`, `first/after`, and mutations (`create`, `update`, `delete`, `upsert`).
- All HTTP goes through `ApiClient` from `@microsoft/rayfin-lib` (injected into `DataApi`).
- GraphQL helpers use DAB-compliant filters and cursor pagination only; booleans and dates are serialized/deserialized for DAB quirks.

## Conventions

- Treat decorated entity classes from `@microsoft/rayfin-core` as **types only**; import them with `import type`.
- Keep `DataApi` zero-knowledge about decorator metadata; do not read `DYNAMIC_METADATA_STORAGE` here.
- Maintain 100% DAB compliance:
  - GraphQL filters are object-based (no OData strings).
  - Logical operators are lowercase (`and`, `or`).
  - Pagination is cursor-based (`first/after/last/before`).
- Use the Proxy pattern consistently for per-entity clients; add new behavior in the client classes, not in the proxy traps.

## Testing

- Unit tests live under `src/__tests__/` and use `vitest`.
- Preferred targets:
  - `rushx test` for full suite.
  - `rushx test:watch` during development.
  - `rushx test:coverage` before larger refactors.
- Integration-style tests validate DAB compliance by asserting generated REST/GraphQL requests and response unwrapping.

## Do Not Edit

- `dist/` output and `*.tsbuildinfo` files are generated by the TypeScript build.
- Keep DAB-specific serialization helpers and type definitions in their existing modules; reuse them instead of re-implementing.
