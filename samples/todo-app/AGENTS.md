# Todo App Sample - Agent Context

Scope: Contributors and agents working on `samples/todo-app` inside the Rush monorepo.
Link `README.md` for Contributor-facing setup; this file focuses on implementation, commands, and workflows.

## Commands

Install and build from repository root:

```bash
rush update
rush build --to todo-app
```

Rayfin CLI workflows (run from `samples/todo-app/`):

```bash
# Run Rayfin development backend with Webservice image from GHCR
rushx rayfin:up

# Run Rayfin development backend with local Webservice changes
# Use:
# - When making changes to `packages/host/Microsoft.Rayfin.WebService` or related host packages
# - Testing WebService API changes, middleware, or data/auth/storage integration
# - Debugging WebService issues with breakpoints
rushx rayfin:dev:local

# Run Rayfin development backend rebuilt when changes made to Dockerfile.Development or clean start
rushx rayfin:dev:local:rebuild

# Run Rayfin development backend with purge (clean start)
rushx rayfin:dev:purge

# Generate and apply database schema
rushx rayfin:db

# Generate and apply storage config
rushx rayfin:storage
```

Run the sample from `samples/todo-app/` (preferred via `rushx`):

```bash
# Mock mode (localStorage, no backend)
rushx dev:mock

# Rayfin mode (requires backend running)
rushx dev:rayfin

# Fabric profile (no rebuild)
rushx dev:fabric

# Toggle between modes (edits .env.local)
rushx toggle-mode
```

`dev:mock`, `dev:rayfin`, and `toggle-mode` call `scripts/toggle-service-mode.js`, which edits `.env.local` to pin `VITE_SERVICE_MODE`.
Treat `.env.local` as developer state and never commit it.

Testing, lint, and build (from `samples/todo-app/`):

```bash
rushx test
rushx test:watch
rushx test:ui
rushx coverage
rushx lint
rushx build
rushx clean
rushx preview
```

## Environment

Source of truth: `rayfin/.env` (`RAYFIN_PUBLIC_*` prefix).
`rayfin dev` generates `.env.local` with Vite-compatible names before starting `dev:frontend`.

Vite frontend variables (in `.env.local`):

- `VITE_RAYFIN_API_URL` – Rayfin backend URL (default `http://localhost:5168`); sourced from `RAYFIN_PUBLIC_API_URL`
- `VITE_RAYFIN_PUBLISHABLE_KEY` – Rayfin publishable key; sourced from `RAYFIN_PUBLIC_PUBLISHABLE_KEY`
- `VITE_FABRIC_ITEM_ID` – Rayfin item ID; sourced from `RAYFIN_PUBLIC_ITEM_ID` (written by `rayfin up`)
- `VITE_SERVICE_MODE` – `mock` or `rayfin` (default `rayfin`)

Config files:

- `.env` – defaults for all environments (frontend)
- `.env.local` – generated by `rayfin env --framework vite` (git-ignored); `toggle-mode` also edits this
- `rayfin/.deployments.json` – registry of Fabric workspace deployments (written by `rayfin up`)
- `rayfin/.env` – backend configuration (supports environment variable interpolation in rayfin.yml)
- `rayfin/.env.example` – template showing all supported backend variables

**Environment variable interpolation in rayfin.yml:**

Rayfin CLI supports Docker Compose-style variable substitution in `rayfin.yml`:

```yaml
services:
  data:
    enabled: ${DATA_ENABLED:-true}
    dialect: ${DATA_DIALECT:-mssql}
```

Priority: shell environment > rayfin/.env > default values

Use `--env-file` flag to specify custom env file:

```bash
rushx rayfin:up -- --env-file rayfin/.env.custom
```

If Rayfin initialization fails (network/CORS/backend down), the app logs an error and falls back to mock mode with a user-visible banner.

## Architecture and Services

ServiceContainer pattern controls mock ↔ Rayfin mode:

- `ServiceContainer.create('mock')` → mock services with localStorage persistence
- `ServiceContainer.create('rayfin')` → Rayfin-backed services via Rayfin client

Key service mappings:

- Auth: mock auth service ↔ Rayfin auth service (uses `@microsoft/rayfin-client`)
- Todos: mock todo service ↔ `RayfinTodoService` (GraphQL fluent API)
- Categories: mock category service ↔ Rayfin category service
- Profile images: mock profile image service ↔ Rayfin profile image service (uses `@microsoft/rayfin-storage`)

Custom hooks wrap services for React components:

- `useAuth()` – authentication state and operations
- `useTodos()` – todo CRUD, filtering, and reload
- `useCategories()` – category CRUD and filtering
- `useProfileImage()` – profile image load and upload
- `useAuthSettings()` – available auth methods (password, magic link, Fabric)

## Rayfin Integration Points

Decorators (`@microsoft/rayfin-core`):

- `rayfin/data/Todo.ts` – todo entity with decorators for DAB schema
- `rayfin/data/Category.ts` – category entity with relationships

Storage (`rayfin/storage/`):

- `rayfin/storage/ProfileImage.ts` – blob storage entity for user profile images
- `rayfin/storage/schema.ts` – `TodoAppStorageSchema` type mapping

Client (`@microsoft/rayfin-client`):

- `RayfinClientService` manages a singleton Rayfin client
- `getRayfinClient()` returns the initialized client for services
- `AuthStateObserver` component listens for auth state changes and syncs React state

Data API (`@microsoft/rayfin-data`):

- `RayfinTodoService` uses the GraphQL fluent API (`rayfinClient.data.gql`)
- Queries and mutations are type-safe and DAB-compliant

## Debugging local Webservice changes

### Remote Debugging (Docker Container)

**Setup:**

1. Start local WebService: `rushx rayfin:dev:local` from `samples/todo-app/`
2. In VS Code: Press F5 or go to Run and Debug
3. Select "Attach to WebService (todo-app Docker)" from launch configuration dropdown
4. Debugger restarts the container and attaches to the `Webservice` process inside `todo-app-webservice-1` container

**Diagnostic tools available in container:**

Exec into the container to use diagnostic tools:

```bash
docker exec -it todo-app-webservice-1 /bin/bash

# Process inspection
ps aux | grep dotnet

# .NET diagnostic tools
dotnet-trace collect --process-id <pid>
dotnet-counters monitor --process-id <pid>
dotnet-dump collect --process-id <pid>
```

**Commands (from `samples/todo-app/`):**

```bash
# Run all E2E tests (API + UI)
rushx test:e2e

# API tests only (Vitest, tests SDK against real backend)
rushx test:e2e:api
rushx test:e2e:api:watch
rushx test:e2e:api:debug     # Keeps backend running after tests

# API tests by category
rushx test:e2e:api:core      # Auth tests without email (AUTH_EMAIL_ENABLED=false)
rushx test:e2e:api:email     # Auth tests with email (AUTH_EMAIL_ENABLED=true)

# UI tests only (Playwright, browser-based)
rushx test:e2e:ui
rushx test:e2e:ui:headed     # Run with visible browser
rushx test:e2e:ui:debug      # Debug mode with backend kept running
```

**Architecture:**

- **Shared Backend**: A single Rayfin backend (Docker Compose) serves all parallel test workers
- **Shared Frontend**: Playwright's `webServer` config manages a single Vite dev server (port 5173)
- **Test Isolation**: Each test uses unique user credentials and data to avoid conflicts

**Environment Variables:**

- `E2E_KEEP_BACKEND_RUNNING=true` – Keep backend running after tests for debugging
- `DEBUG_FRONTEND=true` – Enable Vite server output logging

## Workflows

Full-stack Rayfin run for inspection or MCP:

1. From repo root: `rush update` and `rush build --to todo-app`.
2. Build .NET backend: `dotnet build` (solution or WebService project).
3. Run backend: `dotnet run --project packages/host/Microsoft.Rayfin.WebService/Microsoft.Rayfin.WebService.csproj`.
4. In `samples/todo-app`: `rushx dev:rayfin`.
5. Open the printed URL (or use Playwright MCP) and sign in with your Rayfin user.

Mock-mode quick run:

1. From repo root: `rush update`.
2. In `samples/todo-app`: `rushx dev:mock`.
3. Sign in with demo credentials from `README.md` and verify todos.

Local WebService development (testing WebService changes):

1. From repo root: `rush update` and `rush build --to @microsoft/rayfin-cli`.
2. In `samples/todo-app`: `rushx rayfin:dev:local` (subsequent runs).
3. Make changes to C# files in `packages/host/` – hot-reload happens automatically.
4. Attach VS Code debugger (see Debugging section) to set breakpoints and inspect state.
5. Frontend: `rushx dev:rayfin` in a separate terminal to start the React app.

For deeper human-facing docs, see `samples/todo-app/README.md`, `docs/contributor/`, and `packages/guide/assets/docs/`.

## Rayfin data/auth guidance (MCP required)

When generating or editing **data-relation code**, **data-query code**, or **auth-related code**, use the **Project Rayfin MCP** (`mcp_Project-Rayfin_*`) for up-to-date docs and patterns. Call `mcp_Project-Rayfin_get_doc` or `mcp_Project-Rayfin_search_docs` before writing entity or query code.

This includes:

- Data modeling + relations: `@entity`, `@one`, `@many`, inverse relations
- Permissions/roles: `@role`, `@permissions`, `@authenticated`, `@anonymous`
- Data API/query code: select/filters/order/pagination
- Auth flows: sessions, sign-in/sign-up, auth SDK usage

Suggested doc entrypoints:

- `guide:docs/guide/data/overview.md`
- `guide:docs/guide/auth/overview.md`
- `ts-sdk:docs/ts-sdk/@microsoft/rayfin-data/index.md`
- `ts-sdk:docs/ts-sdk/@microsoft/rayfin-auth/index.md`
