# AGENTS.md

This project ships agent context: skills under `.agents/skills/` and MCP servers in `.mcp.json`. Load them before writing code.

## Project

React + TypeScript (Vite) app backed by **Project Rayfin** with 45+ Radix-based UI components styled with Tailwind CSS.
Demonstrates authentication, data persistence, and user-owned timestamp tracking.

## Repo map

- `src/` – React UI
- `src/components/ui/` – Radix-based UI components (45+ components)
- `src/components/` – App-specific components (AuthPage, SignInForm, etc.)
- `src/hooks/` – React hooks (AuthContext, useTimeStamps)
- `src/pages/` – Page components (Dashboard)
- `src/services/` – Service layer (ServiceContainer, Rayfin services)
- `rayfin/rayfin.yml` – Rayfin configuration (auth + data enabled)
- `rayfin/data/` – Entities (export from `rayfin/data/schema.ts`)

## UI (Radix-based shadcn/ui)

This project uses **Radix-based UI components** styled with **Tailwind CSS v4**.

- UI components live in `src/components/ui/`
- Utility helper lives in `src/lib/utils.ts` (`cn`)
- Add a component: `npx shadcn@latest add <component>` (example: `npx shadcn@latest add button`)

### shadcn MCP server (preferred for generation)

For shadcn-related tasks (generating UI code/components, finding examples, registry items), prefer the shadcn MCP tools:

- `mcp_shadcn_get_project_registries` (reads configured registries from `components.json`)
- `mcp_shadcn_search_items_in_registries` / `mcp_shadcn_list_items_in_registries`
- `mcp_shadcn_get_item_examples_from_registries` (pulls full demo/example code)
- `mcp_shadcn_get_add_command_for_items` (prints the correct `shadcn add` command)
- `mcp_shadcn_get_audit_checklist` (post-change verification checklist)

Key config/files:

- Global styles + Tailwind import: `src/styles/theme.css`
- Path alias `@/*` → `src/*`: `tsconfig.json`
- Vite plugins + alias: `vite.config.ts`
- shadcn registry/config: `components.json`

## Architecture

### Service Layer (Rayfin-only)

- **ServiceContainer**: Singleton that initializes and provides access to services
- **RayfinClientService**: Manages the RayfinClient singleton instance
- **RayfinAuthService**: Composite authentication service (builder pattern) combining username/password and Fabric auth
- **RayfinUsernameAuthService**: Username/password authentication provider
- **RayfinFabricAuthService**: Fabric/Entra authentication provider
- **RayfinTimestampService**: Timestamp CRUD via DataApi fluent interface

### Routing

- `/auth` – Public auth page (redirects to `/` if authenticated)
- `/auth/callback` – Fabric OAuth callback handler
- `/` – Protected dashboard (redirects to `/auth` if not authenticated)

### Key files

- `rayfin/data/Timestamp.ts` – Entity with decorators and user ownership policy
- `src/services/ServiceContainer.ts` – Service initialization
- `src/hooks/AuthContext.tsx` – Authentication state management
- `src/hooks/useTimestamps.ts` – Timestamp operations hook
- `src/components/AuthPage.tsx` – Auth view manager (login/signup/forgot/reset)
- `src/pages/Dashboard.tsx` – Main dashboard page

## Environment

- `.env` – Default configuration
- `.env.local` – Generated by `rayfin dev` before frontend startup (git-ignored)
- `rayfin/.env` – Runtime and deployment values (git-ignored, managed by Rayfin CLI)

## Code conventions

- TypeScript strict mode; prefer small functional React components.
- Keep UI logic in `src/`; keep data model code in `rayfin/data/`.
- Services follow the singleton pattern via `ServiceContainer`.

## Generated files (do not edit)

- `rayfin/.temp/` – Rayfin/DAB config generation output
- `dist/` – Vite build output
- `.env.local` – Local environment overrides (git-ignored, script-managed)
